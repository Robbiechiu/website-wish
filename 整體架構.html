網站整體架構

網站跟儀表板是親戚：網站的「後台」，其實就是一個儀表板。這頁先讓你看懂一個網站由哪三層組成，再把你要的東西講清楚。

跳到九個問題

每個網站都是這三層

不管是個人介紹、課程報名還是點餐，結構都一樣：前台給客人用 → 後台給你看 → 放上網路。

第一層

前台（客人看的）

  • 介紹：你是誰、賣什麼
  • 動作：報名、點餐、下單、留資料
  • 收資料：名字、電話、選項、照片

先決定：客人看完要做什麼。一頁只放一個主要動作。

→
第二層

後台（你看的）

＝ 一個儀表板
  • 誰報名、誰點了什麼
  • 加總、匯出、傳給別人
  • 改狀態：已付款、已出貨

只展示、不收資料的網站，不需要後台。

→
第三層

上線

  • GitHub 存程式
  • Cloudflare 放網頁
  • 有收資料：加資料庫
  • 有後台：加密碼

這一層儀表板和網站共用同一套步驟。

九個問題

這九題就是 skill 會問你的。在這裡直接點選，結果會即時出現在下面。

第 1 步・前台
1

這個網站是做什麼的？（選一個）

決定前台要長什麼樣、需不需要後台。

2

誰會來看？（選一個）

陌生人要先介紹清楚；認識的人可以直接給動作；會員就要登入。

3

他從哪裡點進來？（可複選）

從 LINE 點開的網站，有一些限制要先避開。

4

看完要他做什麼？（選一個）

一頁只放一個主要動作，按鈕要最大、最好找。

5

要收哪些資料？（可複選）

收越少越好。每多一欄，就少一些人填完。

第 2 步・後台（＝儀表板）
6

收到資料之後，你要做什麼？（可複選）

這就是後台要長的樣子。要看曲線、紅綠燈這類細節，用「儀表板怎麼做」那頁的九題再問一次。

7

誰可以進後台？（選一個）

後台看得到別人的個資，一定要有密碼。

第 3 步・定細節
8

網站要幾頁？（選一個）

大部分一頁就夠。內容多到要滑很久，再分頁。

9

一句話：這個網站成功的樣子是什麼？

最重要的一題。有數字最好，做完才知道有沒有成功。

八條規則：老師做網站踩過的雷

先講「看完要他做什麼」

一頁一個主要動作。介紹寫再多，沒有按鈕讓人報名，就白做了。

後台就是儀表板

收資料的網站，一定要想好收到之後誰看、怎麼看。資料收了沒人看，等於沒收。

一份資料只有一個真實來源

點餐系統的菜單只寫在一個檔，點餐頁和統計頁都讀它。改一次兩邊同步，不會價格對不上。

從 LINE 打開，一定要實測

LINE 內建的瀏覽器有限制：跳出來的輸入框不會出現，Android 手機有時圖片會被擋。要讓人從 LINE 點開，就要在 LINE 裡實際點一次。

先用假資料點一輪

上線前自己當客人，從頭點到尾、送出一次，再去後台看資料有沒有進來。

密碼不寫進程式

後台密碼放在不會上傳的檔案裡。上傳到 GitHub 的東西，要當作別人都看得到。

舊資料不刪，開新一輪

點餐系統「開新的一團」時，舊訂單留著不刪。刪掉就找不回來。

「做好了」要用手機畫面證明

大部分人用手機開網站。請 Claude 交件附手機寬度的截圖，它說「完成」不算。
